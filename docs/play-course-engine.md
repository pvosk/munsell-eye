# Chroma Glider: evaluated course bank, correction pass

**Historical courses-2 design below.** The current courses-3 pass adds competing-route comparisons and a denser multi-start search. See [the current palette × type report](play-competition-report.md) for actual results, selection rules and limitations. The previous bank is retained solely for exact lab replay; it is not the new-course generator.

This is the second bank revision (`courses-2`), not the Lab and not a proof of globally optimal routes. `play-course-report.json` is generated with the bank and contains the actual selected pars, lightness ranges and route-interaction counts.

## What now runs

The build-time evaluator uses the same `spectral.js` mixture, pigment RGB approximations, tinting strengths, absolute accumulated paint quantities, OKLab scoring and mass-dependent charge function as play. Mixing balance is unchanged. All palettes now use an OKLab landing tolerance of .028, removing the previous palette-dependent cup size. The scene draws three mapped sections of that actual boundary rather than an average-radius world-space sphere. Screen-space overlap alone still cannot establish 3D containment.

For each target it evaluates every pure base and every distinct first paint. A redundant initial addition of the base itself is excluded. It samples 65 one-addition hold times, and a 9 × 9 hold-time grid for every two-addition order, including repeated or returning paints. Each order's best sampled point is refined locally. All feasible permutations of the generating recipe supply additional constructive witnesses, including three-addition witnesses. Routes that succeed near the edge of tolerance still count as shortcuts.

Every stored route replays the actual hold times. Perturbing an early hold also changes mass and the dose generated by each later hold, rather than silently preserving later parts. The reported timing margin is the tightest one-coordinate perturbation of the most forgiving sampled shortest route, capped at 300 ms. This is **not** the complete joint setup/finish region.

The live game only selects an entry; it no longer runs the candidate search on the player's phone. Each palette has four seeded five-hole rounds. There are 200 slots and 199 distinct candidate IDs in this bank. A restart retains the same target and round. New Target selects another seeded round at the current hole index and avoids an immediate identical entry.

## Hard conditions and preferences

- Every selected target is at least 1.8 landing tolerances from every pure paint. This is a design exclusion threshold, not a perceptual theorem. There is no fallback that relaxes it.
- Every target must also be at least 6.5 display-world units from every pure paint. Each one-addition order is separately searched over holds from 0–180 ms, at 10 ms spacing followed by bounded local refinement; a successful quick-tap route rejects the target. This is still sampled, not a continuous proof.
- Targets within a round are more than 1.8 tolerances apart. That reduces repetition but does not guarantee non-overlapping acceptance spheres, which would require 2 tolerances.
- An interior tag requires the best sampled/refined one-addition error from **every base** to exceed 1.05 tolerances. The stored route takes at least two additions.
- A chromatic-ride tag requires a one-addition route with target OKLab chroma above .075, sampled route chroma above .055, world length over 10, and target distance over 9 world units from every pure paint. This means sustained chromatic travel, **not** verified contact with the boundary of the palette's gamut.
- A value-finish tag requires a final white/black addition, an OKLab lightness change over .12 on that addition and a final-leg world length over 5.
- Quiet Zorn targets have lightness .4–.88, chroma below .035 and black in the retained recipe. This does not prove black is necessary on every possible route. The current catalogue black is slightly warm, not measured blue-undertone ivory black; these are relative cools/quiet neutrals.
- A choice tag means at least two ingredient sets occur among successful sampled minimum-shot routes. Ingredient presence uses a 1.5% quantity cutoff. It does not yet prove visibly distinct ordered trajectories.
- A precision tag requires an interior target and a best tested timing margin below 70 ms.

Profiles in `play-course-analysis.ts` set different requirements and preferences. Zorn reserves two quiet targets. CMY caps chromatic rides at two, reserves two interiors and one muted target (chroma below .08), and the selected bank brings a muted target before the finale. RYB reserves two interiors and a ride. Secondaries reserves two interiors, another precision target and a ride: at least three multi-addition holes. UltraOx reserves a value finish and two interiors; Chromatic Dark reserves a value finish. French Light reserves an ingredient-choice target. Other positions use palette preferences, color separation, type variety, selective travel-length weighting and a modest preference for tighter multi-addition timing. There is no common five-type rhythm. The finish has the highest selected player par, breaking ties by the smaller timing margin.

Travel preference currently uses the retained route, not a guarantee that every alternative base requires comparable travel. The scene's cubes depict the global calibrated color field; they are not a computed palette-gamut boundary.

## Player par versus route length

`solutionShots` is the fewest additions **found**, excluding the free pure-base selection. `par` is a provisional player allowance:

1. Best-found additions + 1 adjustment shot.
2. +1 if the tested timing margin is below 55 ms; another +1 below 22 ms.
3. +1 for multi-addition routes in the deliberately harder palette profiles.
4. Clamp to 2–6.

The actual selected bank currently spans player pars **2–6**. These allowances are design parameters, not statistics from player sessions. No telemetry or play-history collection was added. Finishing below par is not necessarily a newly discovered shortcut.

## What remains for the next engine pass / Lab

- Joint setup/finish feasibility regions, rather than one-coordinate timing margins.
- Multiple local starts or adaptive cells for stronger shortcut searches; exhaustive three-addition alternatives are not covered.
- Travel and corridor comparisons across all successful bases, not only the retained demonstration route.
- Stronger route-shape diversity and palette-interaction scoring. Current interaction counts describe consecutive paints in selected routes; they do not establish aesthetic merit or historical palette identity.
- Stable-ID player review and empirical par calibration. The IDs and retained route diagnostics are present; there is no Lab UI yet.

To regenerate, bundle `scripts/build-play-courses.ts` for Node with the existing esbuild installation, run it from the project root, then run `scripts/test-play.ts`. Generated palette signatures guard changes to pigment RGB/strength and tolerance; if changing the mixing or control algorithms themselves, regenerate and revalidate too.
